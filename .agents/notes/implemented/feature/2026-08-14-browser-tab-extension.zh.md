# Agent Note: 浏览器标签页扩展提供方

Status: implemented

[English](2026-08-14-browser-tab-extension.md) | 中文

## 问题

运行在 Host 进程中的 agent（智能体）若不启动独立的自动化浏览器，也不跨入浏览器扩展，就无法控制用户现有的浏览器窗口。独立浏览器会使用另一份配置文件并失去用户当前标签页，而 Node 中没有直接浏览器 API。此能力还会处理私有标签页元数据和具有破坏性的关闭操作，因此必须明确规定提供方可达性、审批、陈旧页面清理和结果归属。

## 决策

浏览器标签页组成一项三角色能力。`@deepseek-ai/dsh-browser` 负责 Host 服务、提供方租约、请求生命周期、校验与稳定错误。`@deepseek-ai/dsh-client-browser-extension` 负责 Web Client 提供方和打包的 Chromium MV3 扩展。`@deepseek-ai/dsh-tool-browser` 负责面向模型的提示词、schema、展示与审批行为。

Web Client 只在带版本的页面探测确认内容脚本后注册。注册会返回包含 Host 超时值的可续租租约。Client 在租约时长过半时续租，在 teardown 时断开连接，并在释放竞态期间获得的任何租约前等待正在进行的注册。Host 会清理过期提供方，选择最近出现的存活提供方，并在完成、取消、超时、断开连接、租约过期或服务 dispose（资源释放）时结算每个待处理操作。

Host 到 Client 的命令使用 [Remote 事件交付决策](../architecture/2026-08-10-remote-event-delivery.md)定义的允许名单载体 `ctx.remote.$on('browser/command', ...)`。每条命令携带不透明请求 id 和所选提供方 id。其他提供方返回的完成结果会被拒绝，结果判别字段与操作不同也会失败，而不会被强制转换。

扩展工具栏按钮会打开 MV3 侧栏。扩展自身的壳会探测可配置的明文 HTTP 回环 origin，在响应成功后嵌入完整 Harness Web UI，并把所选 origin 保存到扩展本地存储。默认值是 `http://127.0.0.1:3080`；校验只允许 `127.0.0.1` 和 `localhost` origin。该设计复用已经装配的 Web Client，不会在扩展内创建第二套对话实现。

隔离世界桥使用带版本的请求／响应协议。页面端和内容脚本端会校验每个协议封装、操作、结果、标签页字段与错误代码。内容脚本会在匹配的 frame 中运行，让侧栏 Web UI 能够响应探测。MV3 Service Worker 只接受来自本扩展 id 且 sender 为明文 HTTP 回环地址的 Host 操作消息，只允许打开不含凭据的 HTTP(S) 目标，并路由封闭操作联合。manifest（元数据清单）授予侧栏、存储、Native Messaging、标签页、脚本注入和普通 HTTP(S) 页面访问权限；其 frame/connect 策略只允许使用明文 HTTP 的 `127.0.0.1` 与 `localhost`。当前页面读取、文档绑定操作与 Windows 服务恢复由[页面控制决策](2026-08-16-browser-side-assistant-page-control.md)负责。

Consumer 通过面向模型的工具暴露封闭的标签页与页面操作集。默认情况下，每项操作都会进入普通工具审批链；随附的侧边助手 preset 会显式关闭这层额外审批，因为扩展安装本身已授予浏览器能力，而嵌入式 Web UI 没有审批回答方。保留默认值的部署仍会对列出操作请求审批，因为它会暴露当前浏览器窗口中的 URL 与标题。扩展状态缺失仍是执行错误，因此安装不完整时，面向模型的能力不会静默消失。

## 验证

包测试固定租约选择与过期、错误提供方与结果不匹配拒绝、取消、超时、dispose、协议校验、Chromium 错误映射、Client 注册竞态、心跳续租、侧栏 origin 校验与连接状态、工具栏点击配置，以及完整的服务到工具操作联合。无密钥 Web 快照记录真实回放模型请求中的浏览器提示词与 schema。一个有界面的持久 Chromium 运行会加载未打包 MV3 扩展，在侧栏宽度下渲染完整 Web UI，并通过嵌入页面、内容脚本、Service Worker 与 `chrome.tabs` 的真实路径列出标签页；其他标签页和页面操作也使用同一桥接路径。

## 考虑过的替代方案

**从 Host 启动 Playwright 或 CDP。** 否决，因为这种方式会创建或连接自动化浏览器，而不是为用户当前 Web UI 窗口定义受权限约束的提供方。发现配置文件和连接调试端口还会把 Host 权限扩大到标签页操作之外。

**把 Host 代理、模型工具与扩展桥放进同一个包。** 否决，因为 Host 代码、模型约定、Client 生命周期与扩展产物使用不同编译面，并且归属不同。拆分后每种角色可独立测试，也能防止 Chromium 权限细节进入模型 schema。

**暴露不受限制的页面自动化。** 否决，因为任意选择器、下载、Cookie、截图和不受限制的输入需要更广的权限、隐私规则、结果类型与展示。页面控制决策改为公开有界的文档绑定引用和操作集。

**一次探测成功后永久注册提供方。** 否决，因为页面关闭和网络重置会让陈旧提供方继续被选中。可续租租约无需依赖可靠的断开连接数据包，就能让 Host 掌握权威过期时间。

**为侧栏构建另一套轻量聊天客户端。** 否决，因为它会重复会话、审批、设置、工具结果和插件 slot 行为。嵌入已装配的回环 Web UI 能够保持唯一的对话实现，并让普通 Client 提供方在侧栏中运行。

## 后果

用户必须显式加载打包扩展。侧栏自身会保持一个符合条件的 Web Client 页面打开，同时仍支持独立的回环页面。Host 保持独立于 Chromium，除经过校验的封闭操作联合外，绝不会获得其他扩展权限。`tabs` 权限会在扩展内暴露 URL 和标题，因此随附侧边助手 preset 之外的列出操作保留默认审批。多个已连接页面按可见性和新近程度自动解析，用户无法选择；全部提供方和请求状态都只存在于内存中。
